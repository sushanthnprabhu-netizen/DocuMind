# DocuMind

**AI-powered document intelligence with a local, retrieval-augmented question-answering pipeline.**

DocuMind is a full-stack web application where users create an account, upload documents, and ask natural-language questions about their content. Answers are generated from the user's own documents using TF-IDF retrieval, FAISS vector search, and a locally running Llama 3.2 model served by Ollama, so no cloud LLM API key is needed.

## Features

**Document workspace**
- Upload, list, download, and delete documents from the web dashboard
- Per-user storage: every document operation is scoped to the logged-in account
- Supported formats: PDF, DOCX, XLSX, TXT, Markdown, CSV, JSON

**Retrieval-augmented question answering**
- Text extraction, recursive chunking, TF-IDF vectorization, and FAISS similarity search
- Similarity threshold to avoid answering from irrelevant chunks
- Answers generated by a local LLM from the retrieved context only
- Source attribution (filename and match score) returned with each answer
- Workspace questions such as "how many documents do I have?" are answered directly from the database

**Authentication**
- Email and password registration and login
- Passwords hashed with salted PBKDF2-SHA256
- Server-side sessions using bearer tokens
- CORS configured for the frontend origin

**Local-first**
- Embeddings and retrieval run in-process with no external service
- Generation runs on your machine through Ollama, so document text is never sent to a hosted API

## How It Works

```
                 ┌────────────────────┐
                 │  React Frontend    │
                 │  Dashboard + Chat  │
                 └─────────┬──────────┘
                           │ HTTP / JSON (Bearer token)
                           ▼
                 ┌────────────────────┐
                 │  FastAPI Backend   │
                 │  Auth + Documents  │
                 └────┬──────────┬────┘
                      │          │
            ┌─────────▼───┐  ┌───▼─────────────────────────┐
            │ SQLite +    │  │ RAG pipeline (rag.py)       │
            │ file storage│  │ extract → chunk → TF-IDF →  │
            └─────────────┘  │ FAISS → top-k → prompt      │
                             └───────────────┬─────────────┘
                                             ▼
                                   ┌───────────────────┐
                                   │ Ollama (Llama 3.2)│
                                   └─────────┬─────────┘
                                             ▼
                                   Answer + source list
```

**Ingestion (on upload)**
1. Text is extracted with `pypdf` (PDF), `python-docx` (DOCX), `openpyxl` (XLSX), or a plain read (TXT, MD, CSV, JSON).
2. `RecursiveCharacterTextSplitter` splits the text into overlapping chunks (800 characters, 150 overlap).
3. Chunks are stored in SQLite so the index can always be rebuilt.

**Query (on question)**
1. The question is vectorized with the same TF-IDF vocabulary as the user's chunks.
2. FAISS (`IndexFlatIP` over L2-normalized vectors, i.e. cosine similarity) returns the top-k chunks.
3. Chunks below the similarity threshold are discarded. If nothing qualifies, the system says it found no relevant content instead of guessing.
4. The remaining chunks are assembled into a context block and sent to Llama 3.2 with instructions to use only the supplied context, avoid inventing information, and say so when the context is insufficient.
5. The answer is returned together with the sources that contributed to it.

The FAISS index is per user and is rebuilt in memory from SQLite whenever a document is uploaded or deleted.

## Getting Started

### Prerequisites

- **Python 3.10 to 3.13** (avoid pre-release Python builds: `faiss-cpu` publishes wheels only for stable releases)
- **Node.js 18+** and npm
- **Ollama** ([ollama.com](https://ollama.com)) with the `llama3.2` model
- Git

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/DocuMind.git
cd DocuMind
```

### 2. Set up Ollama

```bash
ollama pull llama3.2
ollama list          # should show llama3.2
```

Ollama must be running whenever you use the assistant. On Windows and macOS the desktop app runs it in the background; on Linux run `ollama serve`.

### 3. Backend

**Windows (PowerShell)**

```powershell
cd backend
py -3.12 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8000
```

If activation is blocked, run `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned` once and retry.

**macOS / Linux**

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
pip install -r requirements.txt
python -m uvicorn main:app --reload --port 8000
```

The API is now at `http://localhost:8000` and interactive docs are at `http://localhost:8000/docs`. The first start can take several seconds while the scientific libraries load.

### 4. Frontend

In a second terminal:

```bash
cd frontend
npm install
npm run dev
```

Open `http://localhost:5173`.

## Usage

1. **Register** an account from the login screen.
2. **Upload** a document (PDF, DOCX, XLSX, TXT, MD, CSV, or JSON) that contains extractable text.
3. Open the **AI Assistant** and ask a question the document answers, for example: *"What are the requirements for graduation?"*
4. Read the answer and the **sources** listed with it.
5. Try a question unrelated to your documents: the assistant should report that it found nothing relevant.
6. **Delete** a document and re-ask: it should no longer be used as a source.

## API Reference

All endpoints except `/health`, `/auth/register`, and `/auth/login` require the header `Authorization: Bearer <token>`.

| Method | Path | Description |
| --- | --- | --- |
| GET | `/health` | Health check |
| POST | `/auth/register` | Create an account; returns a token |
| POST | `/auth/login` | Log in; returns a token |
| POST | `/auth/logout` | Invalidate the current session |
| GET | `/auth/me` | Current user |
| GET | `/documents` | List the user's documents |
| POST | `/documents/upload` | Upload a file (multipart) and index it |
| GET | `/documents/{id}/download` | Download a document |
| DELETE | `/documents/{id}` | Delete a document and its indexed chunks |
| POST | `/assistant/ask` | Ask a question about your documents |

Example:

```bash
curl -X POST http://localhost:8000/assistant/ask \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"question": "What does the document say about deadlines?"}'
```

## Troubleshooting

| Problem | Fix |
| --- | --- |
| `pip install` fails on `faiss-cpu` | You are likely on an unsupported or pre-release Python. Recreate the venv with Python 3.10–3.13. |
| Frontend shows a network or CORS error | The backend must be running on port 8000, and the frontend must be served from port 5173 or 3000. |
| Assistant errors when generating | Confirm Ollama is running (`ollama list`) and that `llama3.2` is installed. |
| "No relevant content" for a valid question | Check the file has extractable text (scanned-image PDFs do not) and phrase the question with words that appear in the document; retrieval is lexical (TF-IDF). |
| `Address already in use` | Another process holds port 8000. Stop it or start Uvicorn on a different port and update `VITE_API_URL`. |
| Reset all data | Stop the backend and delete `backend/app.db`, `backend/rag_store.db`, and `backend/uploads/`. |

## Limitations

- Retrieval is lexical (TF-IDF), so it can miss paraphrased questions that share few words with the source text.
- The TF-IDF vocabulary and FAISS index are rebuilt when documents change, which is fine for personal workspaces but not for very large collections.
- Answer quality depends on the local model and the hardware running it.
- Scanned documents need OCR, which is not included.
- Complex layouts (multi-column PDFs, tables) may lose structure during text extraction.
- Intended for local development and demonstration; it has no production deployment configuration.
